# Saved spatial layouts: interaction evidence and verification

Checked September 7, 2026 against the existing Atomic interaction contract at `3ccd536b3851f3c9003cd14cad8307ad9380f430`. These recommendations concern access and recoverability. They do not establish that a 3D task map improves attention, motivation, or outcomes for any neurotype.

## Applied evidence

- **Every move needs a tap alternative.** WCAG 2.5.7 (AA) requires a single-pointer alternative to dragging; keyboard support alone is insufficient. Keep named directional and depth buttons alongside direct manipulation. Camera orbit and zoom also need ordinary controls because their gesture alternatives must not depend on a precise path or multiple fingers. [W3C dragging guidance](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html), [pointer gestures](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures).
- **Motion must remain a choice.** Nonessential interaction animation can be disabled under WCAG 2.3.3 (AAA). Honor both application and operating-system preferences, including camera inertia and automatic orbit. WCAG 2.2.2 (A) addresses automatic movement; pausing only while hovered or focused is not a persistent pause. Keeping optional motion off initially is this product's choice, not a finding that all users prefer stillness. [W3C interaction animation](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html), [pause, stop, hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html).
- **Depth cannot shrink away access.** WCAG 2.5.8 (AA) sets a 24 CSS pixel target minimum with defined exceptions; the app's existing 44 pixel target is a stronger product target. Verify screen-space targets after projection and retain the equivalent task navigator for hidden or crowded particles. Verify that toolbars and popovers do not obscure focused controls. [W3C target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [focus not obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html).
- **Check rendering capability before relying on it.** Three.js documents a WebGL2 capability check. An accessible flat view that preserves the same tasks and saved layout is the product fallback; the documentation does not prescribe that fallback. OrbitControls exposes rotation, pan, zoom, damping, and auto-rotation separately, so disabling decorative motion need not remove direct camera control. [Three.js compatibility](https://threejs.org/manual/en/webgl-compatibility-check.html), [OrbitControls](https://threejs.org/docs/pages/OrbitControls.html).

## Risk-based acceptance matrix

| Priority | Behavior | Required evidence |
| --- | --- | --- |
| P0 | Saved nucleus placement | Move x/y/z through visible controls; reload restores the same scoped record; unchanged areas retain their positions. Compare every canonical task before and after: no x/y, horizon, completion, relationship, or domain-link changes. |
| P0 | Cancel, failure, Undo | Native pointer cancel/Escape restores the preview with no save. Rejected storage writes show failure and retain the last saved layout. Layout Undo and Reset operate on geometry only and survive the documented reload boundary. |
| P0 | Direct touch Undo | A completed primary touch on the horizon Undo button restores the task's prior horizon even if the browser emits no compatibility click. A later compatibility click must not invoke the callback again. Pointer cancellation, swiping, leaving the button, and additional fingers must not activate Undo. Mouse, keyboard, and assistive activation remain available. |
| P0 | Identity and account isolation | Guest layout stays in its documented session scope. Account A cannot hydrate account B's record; sign-out cannot leave A's layout visible. Owner transition during an in-flight save cannot write into the new scope. Use fake identities in model/store tests, not production authentication. |
| P0 | 3D interaction semantics | Rotate the camera, move a nucleus, change its depth, and drag a task at nonzero camera angle. Each action changes only its intended state. Horizon moves still use the existing strict task write and Undo path. |
| P0 | No WebGL / context loss | Denied WebGL2 construction and context loss show a usable fallback with reachable task navigation and layout controls; no unhandled page error or data loss. Capability failure is induced locally, never by changing a user's browser. |
| P1 | Motion and orientation | Fresh 3D opens without automatic motion. Both reduced-motion settings suppress inertia/ambient orbit. Pause remains effective after moving focus. Fit/return-to-flat restores a comprehensible orientation and preserves keyboard focus. |
| P1 | Small screens and overlap | Desktop 1440×1000, touch 390×844, narrow 320×568, landscape 844×390. Verify visible controls can actually receive pointer input, focused controls remain visible, and target/caption overlaps have a reachable navigator alternative. |
| P1 | Corrupt or stale saved data | Validate schema version, finite/bounded coordinates, unknown/deleted domain IDs, storage exceptions, and stale writes in focused model tests. Browser verification checks truthful presentation for at least the storage-failure case. |
| P1 | Existing task relationships | Existing supports/tradeoff/dependency traces and completion contributions retain their meaning after layout changes and across flat/3D. Camera distance must never be presented as relationship strength. |

## Test boundaries

Workflow inventory: `tests/helpers/spatial-layout-workflow.ts` contains the shared control, native input, storage-failure, no-WebGL, and reduced-motion/context-loss workflows. `tests/molecules/spatial-layout.spec.ts` runs those against the local development server; `tests/deployment/spatial-layout.spec.ts` runs the same five workflows at desktop and mobile sizes against the isolated production build. The mobile saved-layout workflow also checks 320×568 and 844×390 pointer targets and focus. These files can be copied into the public harness with relative imports/origin adapted and its `live-fixture` retained as the sole network admission owner.

New browser workflows use fresh anonymous pages, ordinary guide creation, and visible controls. The local test guard admits only the test origin's GET/HEAD traffic and closes WebSockets. Saved tasks/layouts may be inspected read-only for receipts; remote writes, provider requests, or real account switching are outside this browser fixture. The same workflow should remain transferable to the public static-network fixture after a separately verified release.

`AtomicUndoButton.test.tsx` uses callback spies to verify one activation from a completed touch, suppression of its later compatibility click, and no activation after cancellation, swipe, or multiple fingers. It also checks ordinary mouse, keyboard, and assistive activation. The browser workflow records trusted native touch input and durable Week-to-Today Undo in `spatial-native-undo-input.json`; a compatibility click is optional because touch completion itself activates Undo. Browser readback establishes the restored task state, while the unit callback assertions establish duplicate-activation protection.

Run accessibility checks after finite dialog transitions finish, with all applicable rules retained. Axe does not establish canvas hit-target quality, motion comfort, screen-reader comprehension, physical touch behavior, GPU reliability, or preferences. Those require the targeted interaction checks and, where relevant, physical-device and participant evaluation. Report headless Chromium proof at that scope.
